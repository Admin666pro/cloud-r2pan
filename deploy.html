🛠️首次部署准备（一次性）

仅首次需要，之后每次改代码直接用「手动部署」或 CI/CD 即可。

0前置条件

Cloudflare 账户
前往 dash.cloudflare.com 注册 / 登录。
Node.js
安装 Node.js（≥ 18，推荐 20/22），自带 npm。
安装依赖
仅需 wrangler + workers-types + typescript。
npm install

1登录 Cloudflare

npx wrangler login
🔐会打开浏览器并授权 wrangler 访问你的账户，仅需一次。

2创建 R2 存储桶

npx wrangler r2 bucket create crystal-drive

3创建 D1 数据库

npx wrangler d1 create crystal-drive
📌输出里会包含 database_id = "xxxxxxxx-…"，请记下来，第 4 步要用。

4把 database_id 填进 wrangler.jsonc

打开 wrangler.jsonc，把 d1_databases[].database_id 从占位符 LOCAL_PLACEHOLDER 替换为真实值：
"d1_databases": [
  { "binding": "DB", "database_name": "crystal-drive",
    "database_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx" }
]
✅建表由代码自动完成：首次请求时 ensureSchema 会自动创建 files / shares / download_logs / banned_ips / settings / traffic_stats，无需手动导入 SQL。

5设置管理后台密钥 ADMIN_KEY

npx wrangler secret put ADMIN_KEY
⚠️ADMIN_KEY 是登录管理后台的唯一密钥，输入时不会回显，请务必设置并妥善保管。建议 ≥ 16 位随机字符串。

⌨️手动部署（deploy 指令）

以下命令在项目根目录执行，对应 package.json 中已定义的脚本。

本地预览开发调试

npm run dev
# 等价: npx wrangler dev
🖥️默认地址 http://localhost:8787，首页自动跳转 /admin。本地会读 .dev.vars 里的 ADMIN_KEY，D1/R2 为本地模拟。

正式发布部署到 Cloudflare

npm run deploy
# 等价: npx wrangler deploy

线上日志实时日志

npm run tail
# 等价: npx wrangler tail

https://crystal-drive.<你的账号>.workers.dev/admin，用 ADMIN_KEY 登录。

🔗绑定名称（Binding 一览）

代码中直接引用这些绑定名，请勿改动；如需改名必须同步修改代码。资源名与 Worker 名同为 crystal-drive。
绑定名称类型资源名称作用
BUCKETR2 Bucketcrystal-drive存储上传的文件对象
DBD1 Databasecrystal-drive元数据 / 分享 / 日志 / 配置 / 流量统计

🤖工作流部署（CI/CD · GitHub Actions）

推送到 main 分支（或手动触发）即自动部署。以下为推荐配置，创建文件 .github/workflows/deploy.yml 即可。

①在 GitHub 配置 Secret

名称类型说明
CF_API_TOKENSecretCloudflare API 令牌，需 Workers Scripts: Edit + R2 + D1 权限
CF_ACCOUNT_IDSecretCloudflare 账户 ID（首页右下角可查）
D1_DATABASE_IDSecret第 3 步拿到的 database_id，CI 替换占位符用
ADMIN_KEYSecret（可选）如想完全自动化再由 CI 设置密钥；否则建议 CI 外手动设一次
🎫获取 CF_API_TOKEN：Cloudflare 右上角 My Profile → API Tokens → Create，模板选 Edit Cloudflare Workers，再勾选 R2 / D1 权限。

②创建 .github/workflows/deploy.yml

name: Deploy Worker

on:
  push:
    branches: [main]
  workflow_dispatch:        # 允许在 GitHub 页面手动触发

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - name: Install dependencies
        run: npm ci

      # 用 GitHub Secrets 注入 D1 database_id，替换占位符
      - name: Inject D1 database_id
        shell: bash
        run: |
          sed -i "s/LOCAL_PLACEHOLDER/${{ secrets.D1_DATABASE_ID }}/g" wrangler.jsonc
          grep -n "database_id" wrangler.jsonc

      - name: Deploy to Cloudflare Workers
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CF_API_TOKEN }}
          accountId: ${{ secrets.CF_ACCOUNT_ID }}
          command: deploy

③关于 ADMIN_KEY 的两种处理

方案 A · 推荐
方案 B · 完全自动化
✅在 CI 外手动执行一次 npx wrangler secret put ADMIN_KEY（见「首次准备 ⑤」）。密钥持久化在 Cloudflare，CI 只负责代码部署，无需重复设置。
- name: Ensure ADMIN_KEY secret
  env:
    CF_ACCOUNT_ID: ${{ secrets.CF_ACCOUNT_ID }}
    CF_API_TOKEN: ${{ secrets.CF_API_TOKEN }}
  run: |
    echo "${{ secrets.ADMIN_KEY }}" | npx wrangler secret put ADMIN_KEY --name crystal-drive
⚠️需要额外在仓库配置 ADMIN_KEY Secret；已有密钥时命令为幂等（保留旧值）。

❓常见问题

首页 500 / 报 D1 错误？
确认 wrangler.jsonc 里的 database_id 已替换为真实值，而不是 LOCAL_PLACEHOLDER。
一直登录失败？
确认已执行 npx wrangler secret put ADMIN_KEY，且输入与 ADMIN_KEY 完全一致（注意大小写）。
上传后 R2 里找不到文件？
确认 R2 桶名 crystal-drive 已创建，且与 wrangler.jsonc 中的 bucket_name 一致。
想部署到别的名称？
修改 wrangler.jsonc 的 name 字段即可。
文件上传有大小限制吗？
单文件上限 100 MB（Worker 请求体限制），前端会拦截超限文件并提示。
